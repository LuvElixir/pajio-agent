# 人格包

2026-10-12。决策依据见 [0001 · 中立底座 + 人格包 + 邀请码](../decisions/0001-platform-and-persona-packs.md)。

人格包决定 Agent **是谁**：名字、性格、语气、角色设定和形象。它不决定 Agent **能做什么、不能做什么**，后者属于平台规则，所有人格共用。

## 格式

每个人格包是 `src/pajio/personas/<id>/` 下的一个目录，随版本一起发布：

| 文件 | 内容 |
| --- | --- |
| `persona.json` | 清单：`id`、`version`（整数，从 1 起）、`name`（对用户显示的名字，≤20 字）、`summary`（≤120 字）、`appearance`（客户端形象资源编号） |
| `persona.md` | 人格设定，≤4000 字 |

加载时会校验：编号格式为小写字母、数字和连字符，目录名与清单编号一致，清单不允许出现未定义的字段，人格设定不能为空或超长，也不能包含平台规则的标题。

第一个人格包是 `pajama-bear`（睡衣小熊 Pajio）。

## 和平台规则的组合

引擎的 `SOUL.md` 由两段拼成：

```
<persona.md 的人格设定>

# 平台规则
以下规则由 Pajio 平台提供……优先于上面的人格设定……
<src/pajio/platform.md>
```

平台规则包括角色说明、**安全底线**（不做恋爱或依恋导向的互动、危机识别与 12356 心理援助热线、未成年人保护、不生成色情内容、不冒充真实的人）和全部工作方式。每次运行时，相同的组合文本会随请求下发，覆盖旧会话缓存的身份设定。

`pajio-profile.json` 会记录本次应用的人格：`{"id", "version", "sha256"}`。切换人格或升级版本时，旧的 `SOUL.md` 会先备份到 `pajio-backups/`；用户自己改过的 `SOUL.md` 不会被覆盖。

## 记忆的边界

人格包里的"记忆"仅指角色背景和设定。关于用户本人的记忆由平台的记忆工具管理，只属于该用户，不随人格包流转，也不会写进人格包。人格包不得包含真实个人的资料或聊天记录。

## 人格怎么绑定到用户

每个邀请码在签发时就绑定了一个预留的租户实例（独立 VM）。人格在**创建实例时固定**，之后不能更改，因此邀请码通过实例绑定人格：

1. 运营人员为新用户预留租户和资源。
2. 创建实例时选定人格：`pajio tenant init --root … --tenant-id … --origin … --persona <id>`；用 `deploy/tenant/bootstrap.py` 供应 VM 时，在部署上下文里加 `"persona": "<id>"`。不指定时使用默认人格。
3. 为该租户签发邀请码。用户凭码注册后，进入的就是装好对应人格的 Pajio。

人格包编号不存在时，实例不会被创建。人格包的版本随发布走：同一人格的新版本在实例下次启动引擎时生效。在人格包出现之前创建的实例没有记录人格，按默认人格处理。

本机开发时用 `pajio persona list` 查看内置人格，`pajio persona use <id>` 选择人格（写入数据目录下的 `persona.json`），`pajio persona show` 查看当前人格；重新启动引擎后生效。

## 客户端看到什么

`/api/bootstrap` 返回 `persona` 字段：`id`、`version`、`name`、`summary`、`appearance`，不包含人格设定原文。客户端按 `appearance` 选择内置的形象资源。

## 尚未完成

- App、网页和桌面端仍然直接使用小熊的形象和"Pajio"的名字，还没有改成按 `persona` 字段渲染。只要人格仍是小熊，界面就不受影响；新增第二个人格之前必须先完成这一步。
- 邀请记录本身还没有人格字段，注册页因此无法在登录前显示"谁在等你"。这需要一次 PostgreSQL 迁移，并在专用测试集群上验收。
